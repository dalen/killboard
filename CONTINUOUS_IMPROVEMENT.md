### Recent Teammate History feasibility conclusion (2026-11-26)

Do not implement client-side from the current schema. `ScenarioRecordFilterInput` can express `startTime.lt` and `scoreboardEntries.some.characterId.eq`, but generated `QueryScenariosArgs` has no ordering input. A live `scenarios(first:50)` request returned scenario start times in nonchronological order. Therefore `first:N` per character cannot be relied on to select the latest N appearances, and retrieving every earlier scenario to sort client-side would be unbounded. `Character` exposes no scenario history connection.

A live bounded-alias probe for the populated 10-player Garden of Morr match returned 30 rows per each of ten participants in one GraphQL HTTP request in 1,191ms with a 313,520-byte response. It duplicated scenario roster data for every alias, while current matches can reach at least 36 players (observed in the live API's latest 50 scenario records). This is evidence the alias approach is possible but not an efficient, ordered data contract for the feature.

Exact Dalen API addition requested: a batched resolver such as `scenarioTeammateHistory(characterIds: [ID!]!, before: DateTime!, limit: Int!): ScenarioTeammateHistory!`, capped at 30 and strictly excluding scenarios whose `startTime >= before`. Return a de-duplicated set of scenario appearances ordered newest-first, with scenario ID/name/start time and only the requested current-match participant IDs plus their team/realm; also return per-participant coverage metadata (`hasMore` or an explicit complete-through/retention indicator). The resolver must define deterministic descending time order, apply the bound and per-character latest-N selection server-side, and avoid scanning or returning all earlier history. One request should supply all current match participants; no per-combination resolver calls. This supports honest last-10/20/30-window counts/streaks, teammate profile links, and responsive client rendering. Consecutive-streak definition still needs to be displayed in-product: count successive scenario appearances involving any group member where all group members participated together on the same realm; scenarios involving none of that group do not break the streak. Do not call groups premades.
